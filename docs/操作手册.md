# kbserver 操作手册（P0 验收）

> 对应：`docs/方案文档.md` v0.11 · §7 P0 交付判据
> 范围：P0 服务骨架（capture API + 归一化落盘 + 去重 + error 态路径）。P1 及之后的浏览器扩展/手机投递/集合同步/AI 整理/索引检索不在本手册范围。
> 字段与枚举的完整定义以方案文档 §4 为准，本手册只列检查点。

## 0. 环境准备

```powershell
# 1) Python ≥ 3.12
python --version

# 2) 安装依赖（在仓库根 d:\biancheng\otherProject\my_buddy 下执行）
#    注意用 `python -m pip` 而不是裸 `pip`：后者可能被 PATH 上其他 Python 抢走，
#    把依赖装错到全局 site-packages（详见 §4 常见问题）
python -m pip install -r requirements.txt

# 3) 测试基线（预期：27 passed）
python -m pytest -q
```

## 1. 启动与停止服务

```powershell
python -m kbserver
```

- 控制台出现 `Uvicorn running on http://127.0.0.1:8765` 即启动成功。
- 健康检查（浏览器或另开终端）：`Invoke-RestMethod http://127.0.0.1:8765/` → 返回 `{"service":"kbserver","version":...}`。
- 停止：在服务窗口按 `Ctrl+C`。
- 首次启动会自动创建 `kb/` 五区目录（inbox / sources / collections / wiki / index.db 位置占位）。

> 以下所有命令均在**另一个终端**、仓库根目录下执行；服务窗口保持运行。

## 2. 验收用例

### 用例 1：命令行投递 URL 并正确落盘（P0 主判据）

```powershell
python -m kbserver.cli submit "https://www.example.com" --title "验收-正文抓取"
```

预期：

1. 立即返回（受理即结束）：`{"accepted": true, "entry_id": "<12位hex>", "duplicate": false}`
2. 等待 5~15 秒（管道每 2 秒轮询 + 网络抓取），查询状态：

   ```powershell
   python -m kbserver.cli status
   ```

   预期：`sources_entries: 1`，`inbox` 全为 0，`errors` 为空。
3. 检查落盘（路径中的 id 换成上一步返回的 `entry_id`）：

   ```
   kb/sources/web/2026/<entry_id>/
   ├── note.md          # frontmatter + 正文 Markdown
   ├── raw/page.html    # 原始网页（永不覆盖）
   └── meta.json        # content_hash / original_url / raw 清单
   ```
4. `note.md` frontmatter 检查点（对照方案文档 §4.2）：

   | 字段                           | 预期                                         |
   | ------------------------------ | -------------------------------------------- |
   | `id`                         | 与`entry_id` 一致                          |
   | `platform` / `source_type` | `web` / `social`（example.com 命中兜底） |
   | `status`                     | `normalized`                               |
   | `tags`                       | `[]`（AI 未接入前恒为空）                  |
   | `url`                        | 规范化后的 URL（无追踪参数）                 |
   | `captured_at` / `title`    | 投递时间 / 投递标题                          |
5. 正文为 Markdown 提取结果（example.com 是一段英文说明文字）。

### 用例 2：HTTP API 投递（浏览器扩展 / 手机同协议）

任选一个你常读的网页 URL：

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/api/capture `
  -ContentType "application/json" `
  -Body '{"url":"https://www.python.org/","title":"验收-HTTP投递","entry":"browser_ext"}'
```

预期：返回 `accepted: true`；等待管道处理后 `status` 中 `sources_entries` +1，落盘到 `sources/web/2026/<id>/`。

### 用例 3：幂等受理与去重归档

```powershell
# 再次投递与用例 1 完全相同的 URL
python -m kbserver.cli submit "https://www.example.com" --title "验收-重复投递"
```

预期：

1. 受理幂等：`entry_id` 与用例 1 相同，`duplicate: true`（不覆盖已有受理记录）。
2. 等待管道处理一轮后查 `status`：`archived: 1`；`kb/inbox/_archived/` 下出现归档目录。
3. `sources/` 下该 URL 仍只有一份 `note.md`（判重以规范化 URL 幂等）。

### 用例 4：error 态与重跑（P0 判据：失败可观测、可复活）

```powershell
# 投递一个不可达 URL（本机保留端口，必然连接失败）
python -m kbserver.cli submit "http://127.0.0.1:9/" --title "验收-error态"
```

预期：

1. 约 8 秒内三次尝试失败后转 error：`python -m kbserver.cli status` 显示 `inbox.error: 1`，`errors[]` 中含 `error_stage: "fetch"` 与 `error_message`。
2. error 详情落在 `kb/inbox/<id>/capture.json`（normalize 前无 meta.json，状态载体为 sidecar，见方案文档 §4.2）。
3. 重跑指令复活：

   ```powershell
   # <id> 换成 status 中 errors[0].id
   Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/api/entries/<id>/rerun
   ```

   预期：返回 `{"rerun": true}`；`capture.json` 中 `status` 回到 `inbox`、`attempts` 归 0、error 字段清除。
4. 该 URL 本身不可达，重跑后仍会失败——属预期；"重跑成功复活"的完整链路由测试用例 `test_error_state_and_rerun` 覆盖。
5. 巡检完可删掉该条目：删除 `kb/inbox/<id>/` 目录。

### 用例 5：文本条目（无 URL 随手记）

```powershell
python -m kbserver.cli submit --text "验收：随手记一条想法" --title "验收-文本条目"
```

预期：落盘 `kb/sources/web/2026/t.../note.md`；`entry_id` 以 `t` 开头（时间戳+随机）；frontmatter **无** `url` 字段。

### 用例 6：token 鉴权与配置掩码

```powershell
# 设置 token（热生效）
Invoke-RestMethod -Method Put -Uri http://127.0.0.1:8765/api/config `
  -ContentType "application/json" -Body '{"config":{"token":"test-token"}}'

# 无 token 请求 → 401
Invoke-RestMethod http://127.0.0.1:8765/api/status        # 预期报 401

# 带 token → 200，且 token 掩码显示
Invoke-RestMethod http://127.0.0.1:8765/api/config -Headers @{ "X-KB-Token" = "test-token" }
# 预期 "token": "******"

# 回传掩码值 = 保持原值；清理：恢复为无鉴权
Invoke-RestMethod -Method Put -Uri http://127.0.0.1:8765/api/config `
  -Headers @{ "X-KB-Token" = "test-token" } `
  -ContentType "application/json" -Body '{"config":{"token":""}}'
```

预期：掩码不回显明文；回传 `******` 后原 token 不变（日志中同样无明文）。

### 用例 7：条目查询 API（Query API 骨架）

```powershell
Invoke-RestMethod "http://127.0.0.1:8765/api/entries"                      # 列表（含过滤参数 platform/source_type/status）
Invoke-RestMethod "http://127.0.0.1:8765/api/entries/<entry_id>"          # 详情：frontmatter + body + meta + raw_files
```

预期：列表字段与 frontmatter 一致；详情能取到正文与 meta。

### 用例 8：索引重建端点（P4 占位）

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/api/index/rebuild
```

预期：`503`，detail 说明索引引擎 P4 交付（API 骨架先行）。

### 用例 9：重启恢复（运维者姿态 · 方案文档 §10.5）

1. 保持 `kb/inbox/` 中存在 `status: inbox`（刚投递未处理）与 `status: error` 条目各一条。
2. 重启服务（`Ctrl+C` 后重新 `python -m kbserver`）。
3. 预期：inbox 条目被自动继续处理（断点续跑）；error 条目保持 error 等待重跑，不丢失、不静默跳过。

## 4. 常见问题

| 现象                              | 处理                                                                                                                                                                                                                                                                           |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `connection failed`             | 服务未启动或端口不符：核对`python -m kbserver` 是否在跑；CLI 用 `--base http://127.0.0.1:8765` 指定地址                                                                                                                                                                    |
| 装完依赖仍`ModuleNotFoundError` | venv 没装 pip，裸`pip` 沿 PATH 落到了全局 Python（看 pip 输出末尾 notice 指向的路径即可证实）。处理：`python -m ensurepip --upgrade` 先在 venv 内引导 pip，再统一用 `python -m pip install ...` 装包；重新激活 venv 后用 `pip --version` 确认指向 venv 的 Scripts 目录 |
| 端口被占用                        | 编辑`kbserver.config.json`（仓库根）改 `port`，重启服务；CLI 同步换 `--base`                                                                                                                                                                                             |
| 控制台中文乱码                    | PowerShell 执行`chcp 65001`，或用 `python -X utf8 -m kbserver.cli ...`                                                                                                                                                                                                     |
| 抓取一直 error_stage=fetch        | 目标站点不可达或反爬；该条目保留 raw 等重试（正文提取质量分层见方案文档 §5.3 第 2 条）                                                                                                                                                                                        |
| 想调整轮询/重试次数               | `kbserver.config.json` → `pipeline.poll_interval` / `pipeline.max_attempts`，保存后重启服务                                                                                                                                                                             |
| 想关闭图片本地化                  | `kbserver.config.json` → `normalize.image_localization: false`                                                                                                                                                                                                            |
| 误删`kb/`                       | `index.db` 可重建不慌；`sources/` 是唯一事实源，靠 §6 部署形态中的文件级备份兜底（P1 起配备份脚本）                                                                                                                                                                       |
